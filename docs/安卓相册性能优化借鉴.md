# 相册性能优化：借鉴安卓相册的做法

> 目标：像主流安卓相册那样——载图快速、同屏预览数千张、自由滑动不卡顿、点击秒开查看。
> 本文档盘点本项目（全能看图王 / Kanitu）现状与该目标的差距，列出可借鉴的实现手段与落地路线。

## 1. 现状与差距

| 维度 | 主流安卓相册（Google Photos / 各厂相册） | 本项目现状 | 结论 |
|---|---|---|---|
| **DOM 数量** | RecyclerView 虚拟化：几千张图只挂载可视区 ± 缓冲区约几十个 ItemView，滑动时回收复用 | `LibraryBrowser` 网格 `folderImages.map(...)` **全量渲染**：5000 张 = 5000 个 DOM 卡片 | ❌ 最大差距 |
| **可见性观察** | 列表框架统一管理 | 每个 `BlobImage` **各自 `new IntersectionObserver`**（几千个 IO 对象） | ❌ 内存/回调开销 |
| **滚动预取** | 按滚动方向预解码下一屏（RecyclerView prefetch） | 当前目录全量(P1)+子文件夹(P2)+全库预热(P3)后台预取，四级优先级；按滚动方向的精细预取未做 | ⚠️ 大部已覆盖 |
| **解码线程池 + 优先级** | 多线程 + 优先级 | ✅ 4 个 sharp worker + 可见优先队列（`main.ts`） | ✅ |
| **内存 LRU** | ✅ | ✅ 渲染端 `thumbnailCache`（仅按容量 256MB）+ 主进程 `thumbCache`（512MB） | ✅ |
| **磁盘持久化** | ✅ 缩略图数据库 | ✅ `userData/thumbcache`（SHA1 键 = 路径+mtime+size+尺寸+版本，1.5GB 封顶自动清理） | ✅ |
| **渐进显示**（先用缩略图占位，原图解码后替换） | ✅ | ✅ 查看器已实现（占位 → 换入，无黑屏） | ✅ |
| **缩略图规格一致** | 固定裁剪尺寸 | ✅ `aspect-[4/3]` + `object-cover` + `object-top` | ✅ |

**核心判断**：重的活（解码 / 缓存 / 持久化）已经和安卓对齐；卡顿点在**渲染层**——
全量 DOM + 每卡一个 IO + 整树重渲染，这才是"数千张同屏滑动"卡顿的主因。

## 2. 可借鉴的做法（按性价比排序）

### 2.1 网格虚拟化（windowing）——最大收益
- 卡片尺寸固定（`aspect-[4/3]`、固定列数与间距），由容器宽度算出列数；
- 用 `scrollTop` 计算可视行区间，**只挂载可视区 ± 1~2 屏**的卡片，上下以占位 spacer 撑住滚动条高度；
- 一次渲染的 DOM 从 5000 降到几十个；滚动时只替换区间内条目，新增条目走缓存（内存/磁盘命中即出图）；
- 实现方式：自定义虚拟列表（本项目列数可算、卡片定高，完全可行）；或引入 `react-window`（声明式更省事，多一个依赖）。
- 涉及文件：`packages/ui/src/LibraryBrowser.tsx`（图片网格）。

### 2.2 合并 IntersectionObserver——低风险小改动
- 模块级**共享一个 IO 单例**，网格内所有卡片 `observe`/`unobserve` 同一个观察器；
- 替换"每卡片一个 IO"，消除几千个 IO 对象的内存与回调成本。
- 涉及文件：`packages/ui/src/BlobImage.tsx`（或抽到公共模块，LibraryBrowser 统一驱动）。

### 2.3 滚动方向预取
- 滚动时按方向对**下一屏**缩略图提前排入 worker（低优先级），未命中磁盘缓存时后台预生成；
- 与磁盘缓存叠加后，滚动基本无空白格；与安卓 RecyclerView prefetch 同思路。
- 涉及文件：`packages/ui/src/thumbnailCache.ts`（新增滚动预取入口）、`LibraryBrowser.tsx`（滚动事件接线）。

### 2.4 object URL 小池
- 现状：每张图挂载 `createObjectURL`、卸载 `revoke`；
- 改进：对"近期展示过的 Blob"保留 30~60 个 URL 的小池复用，减少创建/撤销抖动。
- 涉及文件：`packages/ui/src/BlobImage.tsx`。

### 2.5 已就位、无需再动
- 多线程解码（4 worker）、可见优先调度、两级 LRU、磁盘持久化缓存、查看器渐进显示、滚动位置记忆（rAF 节流）。

## 3. 落地路线图

| 阶段 | 内容 | 文件 | 验收 |
|---|---|---|---|
| P1 | 共享 IntersectionObserver 单例 | `BlobImage.tsx` | 大文件夹切图/滚动不再随图增多变慢 |
| P2 | 图片网格虚拟化 | `LibraryBrowser.tsx` | 5000 张目录同屏滑动流畅、DOM 数稳定在几十 |
| P3 | 滚动方向预取 | `thumbnailCache.ts`、`LibraryBrowser.tsx` | 快速滚动时白格明显减少 |
| P4（可选） | object URL 小池 | `BlobImage.tsx` | 滚动/切换内存分配曲线更平缓 |

建议先 P1（小、稳），再做 P2（大头）。
