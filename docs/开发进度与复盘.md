## 4. 关键复盘

### 4.1 大图不得通过 JS/IPC 搬运

大图片完整读入 Buffer 或通过 Capacitor bridge 序列化会显著放大内存。当前约束是：缩略图在平台侧降采样，原图通过受控本地 URL 加载，导入与导出使用原生流式路径。

### 4.2 缓存必须定义优先级和生命周期

仅合并 Promise 会让可见请求被后台预取阻塞；仅缓存 URL 又会造成无界内存。当前实现为可见请求升级优先级、缓存容量受限、乱序完成不覆盖有效结果、卸载释放引用。

### 4.3 虚拟化必须与滚动机制一起设计

大量 DOM、每项一个 observer、滚动期间同步布局读取和无界动画会共同造成掉帧。当前网格只挂载可视窗口，使用共享 observer，并在滚动期间限制动画与预取工作。

### 4.4 渐进图片替换不能改变几何布局

缩略图和原图若同时参与 flex 布局，会在原图加载前后改变位置，看起来像错误翻页。两层必须绝对重叠、使用同一尺寸；缩略图保持不透明，原图单向淡入，避免透出黑底造成明暗闪烁。

### 4.5 平台检测必须早于适配器创建

Android bridge 注册是异步的，不能只依赖延迟出现的全局对象。入口先通过 Capacitor 原生标记判断平台，再初始化 bridge，最后创建 Android 适配器和移动 UI。

### 4.6 历史状态只能有一个权威来源

UI 栈和浏览器历史各维护一份计数容易产生竞态。移动端以 `history.state` 快照对账，浮层和目录导航都通过同一栈恢复。

### 4.7 删除失败先看句柄，再看权限

Windows 上目标被占用时 `unlink`/`rename` 立刻失败（EBUSY/EPERM），而占用方往往只持有毫秒级，所以表现为"偶发删除失败、重试又好了"。桌面端曾把缩略图源文件路径直接交给 sharp：libvips 按路径打开时不含共享删除语义，整库预热/网格刷新与删除撞在同一张图上就报 EPERM。根因改为先读入内存再解码（打开句柄由此归属 libuv，允许共享删除），删除/改名路径保留退避重试，兜住杀软扫描、资源管理器缩略图、云同步这类外部占用。
