## 2. 关键问题复盘

### 2.1 Electron 二进制下载失败

**现象**：`npm install` 时 `node install.js` 报 `ECONNRESET`。

**解决**：在 `.npmrc` 中配置镜像：

```ini
electron_mirror=https://npmmirror.com/mirrors/electron/
electron_builder_binaries_mirror=https://npmmirror.com/mirrors/electron-builder-binaries/
```

**经验**：Electron 二进制必须走镜像，否则国内网络容易失败。

### 2.2 PowerShell 写入文件带 BOM

**现象**：Vite 启动时报 `Unexpected token '﻿'`，JSON 解析失败。

**原因**：PowerShell 5.1 的 `Set-Content -Encoding UTF8` 会写入 UTF-8 BOM。

**解决**：使用 `.NET` 写文件：

```powershell
$utf8NoBom = New-Object System.Text.UTF8Encoding($false)
[System.IO.File]::WriteAllText($path, $text, $utf8NoBom)
```

**经验**：在 Windows 环境中写源码文件应显式使用无 BOM UTF-8。

### 2.3 Vite 一直加载旧共享包代码

**现象**：App 版本标记已更新，但侧边栏 Tree 版本仍是旧版。

**根因**：之前 `tsc -p packages/*/tsconfig.json` 没有 `noEmit`，导致在 `packages/*/src` 下生成了一堆旧 `.js` 和 `.d.ts`。Vite 解析 `./LibraryBrowser` 时优先命中了旧的 `LibraryBrowser.js`，而不是新的 `LibraryBrowser.tsx`。

**解决**：

1. 删除所有 `packages/*/src` 下的 `.js` / `.d.ts`。
2. 所有 package tsconfig 增加 `"noEmit": true`。
3. 启动时清理 Electron session cache，并给 Vite URL 加 `?v=时间戳` 防缓存。

**经验**：源码目录中绝不能残留编译产物；typecheck 必须 `noEmit`。

### 2.4 父层级图片数为 0、点击无内容

**现象**：父文件夹只有子文件夹时显示 0 images，点击后 `No images in this folder`。

**原因**：之前 `imageCount` 和 `imagesOf` 只统计直属图片。

**解决**：

- `imageCount` 改为递归总数。
- `directImageCount` 记录直属图片数。
- `imagesOf` 保留递归版本用于封面选择。
- `directImagesOf` 用于当前文件夹网格，避免父层级加载全部子孙图片。

### 2.5 根目录加载几百张图导致卡顿

**现象**：进入应用根目录时递归加载所有图片。

**解决**：

- 当前文件夹只显示直属图片。
- 父层级改为“子文件夹卡片列表”。
- 每个子文件夹只加载一张 512px 封面。

### 2.6 大图导致 `Array buffer allocation failed`

**现象**：`library:readBlob` 大量报 `RangeError: Array buffer allocation failed`。

**原因**：每次缩略图/大图都通过 `fs.readFile` 读取完整原图，并复制 Buffer，内存爆炸。

**解决**：

- 新增 `library:readThumbnail`：`nativeImage` 解码后输出 512px JPEG。
- 网格和文件夹封面统一走缩略图。
- `library:readBlob` 对非 GIF 图片使用 `nativeImage` 解码并限制最大 2560px，不再 `fs.readFile` 完整大图。
- GIF 保留原文件读取以支持动画。

**经验**：Electron IPC 不适合传输大文件；缩略图和预览图必须在主进程原生生成。

## 6. 整理落盘：设计与测试说明

**语义**：在选中文件夹（容器）下，依据 `organizeByFolder` 生成的绑定，把目录子树内的文件移动到 `<容器>/<解析路径>`，创建缺失目录、检测冲突，并生成可撤销 manifest。低置信度（<0.5）的文件**不动**（保持保守）。

- `applyOrganize(store, snapshot, containerRelPath, bindings, options)`：返回 `{ manifest, conflicts, appliedCount, skippedLowConfidenceCount }`。冲突策略默认 `skip`（目标已存在则跳过并报告），可设 `rename` 生成 `xxx (2)`。
- `undoOrganize(store, manifest)`：按反向顺序把文件移回原处。
- 实现完全基于 `LibraryStore` 接口，Electron / Memory / 未来 Android 通用，无平台私有路径拼接（用 `ensureFolderRel` 从库根逐级 walk 创建/解析）。

**后续可做**：
- 冲突重命名策略做成 UI 可切换；整理后清理空目录。
- 置信度阈值暴露为设置项。
- 测试目前用 esbuild 打包后在 Node 直接运行（沙箱下 `node --test` 的子进程 spawn 受限，改为进程内执行）。

**验证**：`packages/core/test/organize.test.ts` 覆盖“落盘→re-scan 校验新树→撤销→re-scan 校验还原”与“target-exists 冲突报告”。

## 7. zip 导出：设计与测试说明

**双路径**（`zipLibrary(targetRelPath, onProgress)` 返回 `ZipExportResult`）：

- **Electron（主）**：renderer 调主进程 IPC `library:exportZip` → 主进程用 `archiver`（STORE，即 `zlib.level:0`）把 `userData/albums/<targetRelPath>` 流式写入**保存对话框**选择的路径。读取**原始文件**、边写边落盘，内存安全；zip 内目录结构与图包树一致（子目录导出时包一层自身名称，整库导出时顶层文件夹平铺）。
- **Web/Memory（演示）**：用内置纯 TS STORE zip 编码器（`fs-adapter/src/zip.ts`，无压缩、UTF-8 文件名、CRC32）生成 zip `Blob`，UI 触发浏览器下载。

**约定**：目标为 `''` 表示整库；目标为 `MangaA` 时 zip 里是 `MangaA/...`。

**注意事项**：
- `archiver` 无内置类型，已在 `apps/desktop/electron/archiver.d.ts` 提供最小声明；并加入 `apps/desktop` 的 `dependencies`（打包时需要，不能只作 electron-builder 的传递依赖）。
- Electron 端为流式写盘，大图包不整包进内存；Web 端目前整包在内存（可为后续优化）。

**验证**：`packages/fs-adapter/test/zip.test.ts`（`yauzl` 打开生成的 zip 校验条目）：整库目录结构、子目录包一层、空库空 zip，且校验内置 `index.json` 内容与结构，`npm run test -w @kanitu/fs-adapter`。

**导出带索引**：zip 内额外写入 `index.json`（`{ version, exportedAt, root, folders[], images[] }`）。Web/Memory 用 `fs-adapter/src/exportIndex.ts` 的 `buildExportIndexJson`；Electron 主进程用内联 `buildIndexJson` 生成同一 schema。索引条目不计入 `totalImages`。

## 8. 持久化索引与删除相册：设计与测试说明

**持久化索引**（`packages/core/src/library.ts` + `indexed.ts`）：
- `PersistentIndex` 接口（load/save/clear）+ 内存实现（演示兜底/测试）+ `createIdbPersistentIndex`（IndexedDB，出错优雅降级）。
- `loadOrScan(store, index)`：启动优先读缓存，未命中才 `scanLibrary` 并落盘 → 不再每次启动全量重扫。
- `rescanLibrary(store, index)`：导入/整理/撤销/删除/刷新后重扫并持久化。
- 仅在 Electron（持久库）启用 IDB 持久化；Web/Memory 演示用内存索引，避免跨会话读到过期数据（演示库是临时重生成的）。

**删除相册**（`packages/core/src/remove.ts`）：
- `deleteLibraryFolder(store, relPath)`：解析现有目录（不创建）→ `store.remove`（Memory 移除整棵子树 / Electron `fs.rm` recursive），禁止删除库根。
- UI 加 Delete Album 按钮，`window.confirm` 二次确认，删除后 `rescanLibrary` 刷新并跳到父级。

**验证**：`packages/core/test/library.test.ts`（loadOrScan 缓存命中/首次扫描、rescan 刷新、clear）、`packages/core/test/remove.test.ts`（删除整棵子树、拒绝删库根）。运行 `npm run test -w @kanitu/core`。

## 9. 原图无损查看 / 键盘导航 / 面包屑：设计与测试说明

**原图无损查看**：
- Electron 主进程注册 `kanitu-file://file/?p=<encodeURIComponent(abs path)>` 协议，handler 用 `assertInsideLibrary` 守卫后 `net.fetch(file URL)` 流式返回原始文件 → 查看器不再用 2560px 预览、也不经大 Buffer/IPC。
- `LibraryStore` 新增 `getViewerUrl`/`releaseViewerUrl`：Memory 返回 blob URL（需 revoke），Electron 返回协议 URL（无需释放）。
- 查看器（`Viewer`）改为原图 `<img>`：滚轮缩放、双击切 Fit/100%、拖拽平移、`R` 旋转、`+/−/0/1` 与 `←/→/Esc` 快捷键、相邻图片预取（加载后释放资源）。

**键盘导航**：仅在**看图页**生效——`ArrowUp/ArrowDown` 在当前目录父级的所有同层目录间切换并展示该目录**首张图**（仍在看图，无直属图的同级目录则回落其网格）；`ArrowLeft/ArrowRight` 在当前目录内上一/下一张；`Escape` 关闭看图回当前网格。目录树/网格视图**不绑定**快捷键。

**面包屑**：`crumbs` 沿 `parentId` 上溯得到根到当前目录链，content-header 顶部渲染可点击路径（末级高亮）。

**说明**：查看器/导航为纯 UI，经 `typecheck` 验证；核心逻辑（路径、同级计算）在 core/fs-adapter 层测试。Electron 协议路径需真机验证（本沙箱无法启动 Electron GUI）。

## 10. 右键菜单 / 条目操作 / 设置页 / 整理优化：设计与测试说明

**右键菜单**（`packages/ui/src/ContextMenu.tsx`）：
- 通用 `ContextMenu` 组件（React portal 到 `document.body`，边缘自动收敛到视口内，点击外部/Esc/滚轮/缩放关闭）。
- 图片右键：查看、设为封面/取消固定封面、重命名、复制路径、删除；图包右键：打开、新建子文件夹、展开/收起子目录、重命名、整理、导出 ZIP、复制路径、删除（库根不可重命名/删除）。
- 删除/重命名/新建均改为应用内 Modal（`promptState` 状态机），去除系统原生 `confirm`/`prompt`。

**条目操作**（`packages/core/src/entry-ops.ts`，平台无关）：
- `renameImage` / `renameFolder`：名称 trim、空名/路径分隔符校验、省略扩展名时自动补齐、同名冲突检测，走 `store.move`。
- `deleteImage`：按 `relPath` 解析文件引用后 `store.remove`。
- `createSubfolder`：在指定父目录新建空文件夹，重名报错。
- 辅助：`resolveFolderRef`（按库相对路径逐级解析，不创建）、`resolveImageFileRef`。

**固定封面**（`packages/cover-picker/src/coverPicker.ts`）：
- `pickCover` 新增 `preferredId` 参数，命中即返回 `{score: 2, reason: 'user-pinned'}`，优先于算法评分。
- UI 用 `kanitu-pinned-covers`（folderId → imageId）localStorage 记忆；设为封面/取消固定会立即刷新封面并通知。

**自定义整理规则**（`packages/organizer/src/organizer.ts` + `packages/ui/src/OrganizeRulesModal.tsx`）：
- `CustomOrganizeRule = { id, name, pattern, target, confidence, enabled }`：`pattern` 是匹配**去扩展名文件名**的正则，`target` 是目录模板（`$1/$2…` 替换捕获组），原文件名保留并放入结果目录。
- 自定义规则**优先于内置规则**按数组顺序匹配；无效正则/空目录/含 `..` 的路径被保守跳过。
- 设置页“整理规则”标签：展示内置规则（分隔符/日期/作者/卷话页/Pixiv 编号/标题+编号），自定义规则可增删改、启停、编辑时实时测试预览（示例文件名 → 虚拟路径）。
- 持久化到 localStorage `kanitu-organize-custom-rules`，启动时校验结构过滤非法项。

**整理性能优化**（`packages/core/src/organize.ts`）：
- `applyOrganize` 增加 `folderCache`（目录解析，逐级 memoize）、`fileNameCache`（目标目录直属文件名集合）、`fileRefCache`（直属文件引用），避免对每个绑定重复 `listChildren` 走目录。
- 原实现是 O(文件数 × 目录深度) 的重复扫描，现收敛为每个目录只列一次，大库整理显著提速。
- 新增 `options.onProgress(done, total)` 回调，UI 展示整理进度。

**GIF 缩略图回退**（`apps/desktop/electron/main.ts`）：
- `library:readThumbnail` 对 `.gif` 直接返回原文件字节（`nativeImage.createFromPath` 在 Windows 无法解码动画 GIF），GIF 通常较小，内存可控。
