## 2. 关键问题复盘

### 2.1 Electron 二进制下载失败

**现象**：`npm install` 时 `node install.js` 报 `ECONNRESET`。

**解决**：在 `.npmrc` 中配置镜像：

```ini
electron_mirror=https://npmmirror.com/mirrors/electron/
electron_builder_binaries_mirror=https://npmmirror.com/mirrors/electron-builder-binaries/
```

**经验**：Electron 二进制必须走镜像，否则国内网络容易失败。

### 2.2 PowerShell 写入文件带 BOM

**现象**：Vite 启动时报 `Unexpected token '﻿'`，JSON 解析失败。

**原因**：PowerShell 5.1 的 `Set-Content -Encoding UTF8` 会写入 UTF-8 BOM。

**解决**：使用 `.NET` 写文件：

```powershell
$utf8NoBom = New-Object System.Text.UTF8Encoding($false)
[System.IO.File]::WriteAllText($path, $text, $utf8NoBom)
```

**经验**：在 Windows 环境中写源码文件应显式使用无 BOM UTF-8。

### 2.3 Vite 一直加载旧共享包代码

**现象**：App 版本标记已更新，但侧边栏 Tree 版本仍是旧版。

**根因**：之前 `tsc -p packages/*/tsconfig.json` 没有 `noEmit`，导致在 `packages/*/src` 下生成了一堆旧 `.js` 和 `.d.ts`。Vite 解析 `./LibraryBrowser` 时优先命中了旧的 `LibraryBrowser.js`，而不是新的 `LibraryBrowser.tsx`。

**解决**：

1. 删除所有 `packages/*/src` 下的 `.js` / `.d.ts`。
2. 所有 package tsconfig 增加 `"noEmit": true`。
3. 启动时清理 Electron session cache，并给 Vite URL 加 `?v=时间戳` 防缓存。

**经验**：源码目录中绝不能残留编译产物；typecheck 必须 `noEmit`。

### 2.4 父层级图片数为 0、点击无内容

**现象**：父文件夹只有子文件夹时显示 0 images，点击后 `No images in this folder`。

**原因**：之前 `imageCount` 和 `imagesOf` 只统计直属图片。

**解决**：

- `imageCount` 改为递归总数。
- `directImageCount` 记录直属图片数。
- `imagesOf` 保留递归版本用于封面选择。
- `directImagesOf` 用于当前文件夹网格，避免父层级加载全部子孙图片。

### 2.5 根目录加载几百张图导致卡顿

**现象**：进入应用根目录时递归加载所有图片。

**解决**：

- 当前文件夹只显示直属图片。
- 父层级改为“子文件夹卡片列表”。
- 每个子文件夹只加载一张 512px 封面。

### 2.6 大图导致 `Array buffer allocation failed`

**现象**：`library:readBlob` 大量报 `RangeError: Array buffer allocation failed`。

**原因**：每次缩略图/大图都通过 `fs.readFile` 读取完整原图，并复制 Buffer，内存爆炸。

**解决**：

- 新增 `library:readThumbnail`：`nativeImage` 解码后输出 512px JPEG。
- 网格和文件夹封面统一走缩略图。
- `library:readBlob` 对非 GIF 图片使用 `nativeImage` 解码并限制最大 2560px，不再 `fs.readFile` 完整大图。
- GIF 保留原文件读取以支持动画。

**经验**：Electron IPC 不适合传输大文件；缩略图和预览图必须在主进程原生生成。

## 6. 整理落盘：设计与测试说明

**语义**：在选中文件夹（容器）下，依据 `organizeByFolder` 生成的绑定，把目录子树内的文件移动到 `<容器>/<解析路径>`，创建缺失目录、检测冲突，并生成可撤销 manifest。低置信度（<0.5）的文件**不动**（保持保守）。

- `applyOrganize(store, snapshot, containerRelPath, bindings, options)`：返回 `{ manifest, conflicts, appliedCount, skippedLowConfidenceCount }`。冲突策略默认 `skip`（目标已存在则跳过并报告），可设 `rename` 生成 `xxx (2)`。
- `undoOrganize(store, manifest)`：按反向顺序把文件移回原处。
- 实现完全基于 `LibraryStore` 接口，Electron / Memory / 未来 Android 通用，无平台私有路径拼接（用 `ensureFolderRel` 从库根逐级 walk 创建/解析）。

**后续可做**：
- 冲突重命名策略做成 UI 可切换；整理后清理空目录。
- 置信度阈值暴露为设置项。
- 测试目前用 esbuild 打包后在 Node 直接运行（沙箱下 `node --test` 的子进程 spawn 受限，改为进程内执行）。

**验证**：`packages/core/test/organize.test.ts` 覆盖“落盘→re-scan 校验新树→撤销→re-scan 校验还原”与“target-exists 冲突报告”。

## 7. zip 导出：设计与测试说明

**双路径**（`zipLibrary(targetRelPath, onProgress)` 返回 `ZipExportResult`）：

- **Electron（主）**：renderer 调主进程 IPC `library:exportZip` → 主进程用 `archiver`（STORE，即 `zlib.level:0`）把 `userData/albums/<targetRelPath>` 流式写入**保存对话框**选择的路径。读取**原始文件**、边写边落盘，内存安全；zip 内目录结构与图包树一致（子目录导出时包一层自身名称，整库导出时顶层文件夹平铺）。
- **Web/Memory（演示）**：用内置纯 TS STORE zip 编码器（`fs-adapter/src/zip.ts`，无压缩、UTF-8 文件名、CRC32）生成 zip `Blob`，UI 触发浏览器下载。

**约定**：目标为 `''` 表示整库；目标为 `MangaA` 时 zip 里是 `MangaA/...`。

**注意事项**：
- `archiver` 无内置类型，已在 `apps/desktop/electron/archiver.d.ts` 提供最小声明；并加入 `apps/desktop` 的 `dependencies`（打包时需要，不能只作 electron-builder 的传递依赖）。
- Electron 端为流式写盘，大图包不整包进内存；Web 端目前整包在内存（可为后续优化）。

**验证**：`packages/fs-adapter/test/zip.test.ts`（`yauzl` 打开生成的 zip 校验条目）：整库目录结构、子目录包一层、空库空 zip，`npm run test -w @kanitu/fs-adapter`。
